## VERDICT [A19-2] `invalidate_btree_cache` clears page stack without unpinning: pinned-page leak -> CacheError(Pinned)
- verdict: FIXED-AT-HEAD (fixed by 496c24ed)
- severity: medium (was); now fixed
- repro: not-attempted (present only in pre-fix commits; fixed at HEAD)
- reasoning: Real at f63bd46. `BTreeCursor::invalidate_btree_cache` (`git show f63bd46:core/storage/btree.rs` line 6311) did `for slot in self.stack.stack.iter_mut() { *slot = None; }` then `self.stack.current_page = -1;`. The fix merge 496c24ed (`git diff 496c24ed^1 496c24ed`) replaces exactly those three lines with `self.stack.clear();`. At HEAD (btree.rs:7196-7201) the impl is `self.stack.clear(); self.has_record=false; ...` and `clear()` (8398) calls `unpin_all_and_clear_slots()`. Fixed.

## VERDICT [A19-3] `pending_peer_save` holds raw cursor pointers across IO yields: use-after-free if a peer statement is reset/dropped mid-yield
- verdict: CONFIRMED
- severity: high
- repro: not-attempted (use-after-free — a live repro could silently corrupt the heap or the DB, and a UAF need not deterministically fault; per instructions, reasoned through instead of triggering)
- reasoning: All three pillars verified at HEAD, and I could find no guard that refutes it.
  (a) Raw ptrs ARE parked across a yield: `drive_pending_peer_save` (btree.rs:6081) snapshots peers into `self.pending_peer_save = Some((peers, 0))` (6092) — a `SmallVec<[RegisteredCursor; 4]>` of `NonNull<dyn CursorTrait>` (pager.rs:1428) — then the loop does `unsafe { return_if_io!(peer.as_mut().try_save_position_for_external_balance()) }` (6104-6105). `return_if_io!` returns out of the function with the raw-ptr snapshot still living in `self.pending_peer_save`. On resume it re-reads `peers[*idx]` and derefs with NO re-validation against the registry.
  (b) Nothing scrubs a peer's `pending_peer_save`: `grep pending_peer_save core/` shows the only writes are the field def (871), the initializer (1124), and self-writes inside `drive_pending_peer_save` (6092/6094/6111). `BTreeCursor::drop` (btree.rs:6294) calls only `unregister_cursor`, and `unregister_cursor` (pager.rs:1720) only `swap_remove`s from the registry bucket and toggles has_peers — it never touches any other cursor's parked snapshot. `ProgramState::reset` (vdbe/mod.rs:1017) drops every cursor slot via `c.take()`.
  (c) The yield path is real AND reachable: for an index peer, `try_save_position_for_external_balance` (btree.rs:7235) reaches `return_if_io!(self.record())` (~7297, comment "Index btree: yield IO for overflow chains"). `record()` (6468) yields via `process_overflow_read` (which does `return_if_io!(self.read_page(...))` / `io_yield_one!` at 1396/1406/1432/1461) whenever `reusable_immutable_record` is invalidated AND the cell has a first-overflow page. That "invalidated + positioned" state is genuinely reachable: `get_next_record` (1367/1660) and `do_seek` (6437/6459) both call `invalidate_record()` AFTER moving, leaving the cursor `valid_state==Valid`, `has_record==true`, record un-materialized. A query that positions an index cursor without reading the key (e.g. `SELECT 1 FROM t WHERE big_indexed_col > ?`, k multi-KB → overflow) returns a Row to the app in exactly that state.
  Freeing mechanism: cursors are heap-owned — `Cursor::BTree(Box<dyn CursorTrait>)` (types.rs:3254); `Cursor::new_btree` registers `NonNull::from(&*cursor)` pointing at that Box (types.rs:3282 → register_with_pager). Concrete chain: one connection, R = `SELECT 1 FROM t WHERE k > ?` (index-only cursor on i1, positioned on an overflow key, record invalidated), W = `DELETE FROM t WHERE ...` (opens an i1 index write cursor). Both register on i1's root → bucket len 2 → has_peers=true on both. App steps W → i1 `delete()` → `drive_pending_peer_save` snapshots `[R's i1 ptr]` → `try_save_position` on R → `record()` → overflow read → `return_if_io!` yields; W parked with R's ptr in `pending_peer_save`. App resets/finalizes/drops R (ordinary sequential API use — `del R`, GC finalizer, or `R.reset()`) → R's Box freed, R unregistered, but W's snapshot NOT scrubbed. App drives W's IO and re-steps W → `peers[*idx].as_mut()` derefs the freed allocation → UAF (crash or silent heap corruption that can reach written pages).
  Refutation attempts that FAILED: (1) The `RegisteredCursor` SAFETY doc (pager.rs:1415) only guarantees no *aliasing* ("no other reference live at the same time"), justified by "a Connection runs one statement at a time." The UAF is sequential, not concurrent — R is freed while W is parked (not running) — so it does NOT violate the aliasing invariant, yet nothing guarantees R's *lifetime* across W's yield. (2) No connection/statement busy-guard blocks resetting R while W has pending IO: the `busy` flag (statement.rs:293) is per-statement; `Statement::reset`→`reset_internal` (1330/1487) operates on R's own ProgramState + pager and never inspects sibling statements, ending in `self.state.reset()` (1533) which frees R's cursors. (3) The yield is genuinely surfaced to the app: `drive_pending_peer_save` is called via `return_if_io!` from `insert`/`delete` (6513/6541), which propagate through the VDBE op to `step()` → `StepResult::IO`, handing control back to the app before W resumes.
