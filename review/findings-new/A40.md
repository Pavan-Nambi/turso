## [A40-1] Connection-level metrics double-count when a prepared statement is reused (reset + step)
- commit: 5b0ebe27ab1d14f247d935d07e5b57e9fc6379f4 "sqlite3: Implement `sqlite3_stmt_status`" (2026-04-07)
- file: core/vdbe/mod.rs (ProgramState::reset, ~line 999) + core/statement.rs:590 (record_statement on Done)
- at-head: present
- category: logic
- severity: low
- confidence: high
- description: To implement `sqlite3_stmt_status` (which must accumulate counters over a prepared statement's lifetime), this commit deleted `self.metrics = StatementMetrics::new();` from `ProgramState::reset()`, so per-statement metrics now persist across `reset()`. But `Statement::_step()` still calls `connection.metrics.write().record_statement(&self.metrics())` on every `StepResult::Done`, and `metrics()` returns the *cumulative* value. When the same prepared `Statement` is reset and re-executed (the normal bind/step/reset loop used by bindings and the sqlite3 C API), each execution adds the running total (not the per-execution delta) into the connection aggregate, so the aggregate and the `max_*_per_statement` high-water marks grow quadratically. Query results, `changes()`, and `total_changes()` are unaffected — this is observability only (exposed via the CLI `.stats`/metrics display which reads `conn.metrics`, and any embedder reading `ConnectionMetrics`). The only metrics reset in the reuse path was the one that was removed; `reset_metrics()`/`reset_stmt_status()` are called only from tests and the explicit `sqlite3_stmt_status(..., resetFlg=1)` path, not from `reset()`/`reset_internal()`.
- failure: Embedder prepares `INSERT INTO t VALUES(?)` once and executes it 100 times, each `reset()`+`step()`-to-`Done` inserting one row. Connection aggregate `rows_written` should be 100; instead it is 1+2+…+100 = 5050, and `max_rows_read_per_statement` reflects the cumulative total rather than the per-execution value. (Not reproducible from the CLI, which prepares a fresh statement per line; requires prepared-statement reuse via a binding or the sqlite3 C API, neither built in this environment. Verified from code: the reset was removed by this commit's diff, `record_statement(&self.metrics())` fires on each `Done`, and `self.metrics()` returns the cumulative `StatementMetrics`.)
