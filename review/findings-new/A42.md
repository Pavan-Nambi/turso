### f8266f20 — `compare records via a normalized 8-byte key prefix` — CLEAN at HEAD

## Detailed analysis: ec19b593 dispatch-loop restructure

Split into an outer `'io_check` loop (checks `io_completions` once) and an inner
loop (dispatches instructions). Two behavioral shifts, both benign:

1. `state.result_row.take()` moved from every inner iteration to once per
   `step()` call. Safe because `ResultRow` returns `Row` immediately, so at most
   one result row is produced per `step()`; the row is valid exactly in the
   window between `step()` returning `Row` and the next `step()` call, which
   clears it at the top. Intermediate instructions never read `result_row`.
2. `is_closed` / `maybe_request_interrupt` moved after the `io_completions`
   check. Interrupt is still evaluated before **every** instruction dispatch, so
   responsiveness is preserved. On resume-after-IO the completion (and its
   errors) is now observed before the close/interrupt check; a closed connection
   with a still-pending IO returns `IO` until the disk op finishes rather than an
   immediate `Connection closed` error — the IO completes normally (disk ops are
   not tied to connection liveness), so it converges to the same error without a
   hang. Finished-IO error observation is preserved via `continue 'io_check`
   (io_completions is re-set to `Some(io)` then re-inspected).
